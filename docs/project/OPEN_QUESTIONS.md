# Open Questions and Assumptions Register

## Purpose

Single consolidated register of every unresolved decision (`OQ-xx`) and every assumption (`A-xx`) recorded across the documentation set. The documentation rule is "never invent": each gap is either an assumption or an open question, and nothing is decided silently. This register is what the user must work through before approving the HLD, LLD, AI architecture and implementation roadmap.

## Scope

All Markdown under `docs/` (BRD, HLD, LLD index and 13 module LLDs, AI documents, security, testing, infrastructure, operations, project documents). Source: 234 open-question ids and 82 assumption ids. Ids that several documents raised for the same question are merged into one row with the other ids listed as aliases; no id was removed (44 merged groups).

## Detailed explanation

### How to read this register
- **Blocking before implementation approval** = the answer changes an architecture, API contract or the primary acceptance test, so the approval gate should not close without it. Count: 27 rows.
- **Blocking before a phase** = can be answered during the project but must be answered before the named workstream (WS1-WS10 of `IMPLEMENTATION_PLAN.md`) starts or finishes. Count: 19 rows.
- **Non-blocking** = a provisional choice in the docs is safe to proceed on; revisit when convenient. Count: 113 rows (includes OQ-700 to OQ-703 and OQ-800 to OQ-816).
- Owners are **roles**, not named people; no owner has been assigned by the user (see OQ-419, OQ-423).
- "Provisional choice" is what the documents currently show; it is labelled PROVISIONAL where it appears and is **not** a decision.

### Cross-document conflicts found while consolidating
1. **LLM call cap — RESOLVED.** The HLD PDF said both 2 and 3 (repair + escalation). ADR-018 removes the escalation tier and sets the cap to **2 LLM calls per task** (initial + one repair); all documents use 2. OQ-20 group is resolved by owner direction.
2. **Source enum raised four times** under different ids (OQ-18, OQ-130, OQ-310, OQ-433), all with the same provisional enum.
3. **Reference-data write path raised four times** (OQ-22, OQ-135, OQ-223, OQ-526), and a fifth time as a role question (OQ-225).
4. **Cost target vs batch budget.** USD 0.50 / 1k records (up to USD 50 for a 100k batch) against the default USD 25 per batch (OQ-15).
5. **AI documents defined OQ-300 to OQ-315 only inline**, without a table. The question text for those ids in this register is taken from the AI writer's summary and the inline context; owners should confirm the wording.
6. **Coverage target:** 85% (HLD, core packages) vs 80% (project rule) (OQ-418 group).
7. **RPO 15 min** is not met by the HLD's daily cross-region snapshot copy (OQ-515).

## Risks and edge cases

- Answering one question can silently invalidate another (for example the LLM cap changes the loop guard, cost and test assertions); resolve merged groups together.
- Provisional choices in the docs can be mistaken for decisions; the approval gate should treat every PROVISIONAL marker as pending.
- Owners are roles only; unowned questions stall. Assigning named owners is itself a pending action.
- Wording for OQ-300 to OQ-315 was reconstructed; confirm it.
